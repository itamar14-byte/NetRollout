# Phase 4 — packaging NetRollout v1.0.0

## Context
NetRollout is feature-complete on `master` (System Settings merged 2026-09-30). Phase 4 turns it into a free community product (GNU AGPL v3) that a team installs with minimal friction: download a release zip, run the installer, answer a few questions, get a running HTTPS NetRollout. This plan records the vision agreed in the planning session and the staged implementation.

_Approved 2026-09-30. Branch `phase-4-packaging`. Status: stages 1–4 done (2026-10-01) — the dev DB is stamped `v1_0_0_baseline`, so `master` can't start against it until the Phase 4 fast-forward; dev settings moved to `config/runtime.env`; next: stages 4b, 5._

## Vision
- **Three uses:** (1) engineer's PC, (2) **team server — main case**: a Windows 10/11 VM running Docker Desktop, reached remotely over HTTPS, (3) **headless CLI** as a standalone `netrollout-cli.exe` (no Docker/Python).
- **Delivery:** public GitHub release zip (v1.0.0, semver) + images on Docker Hub (`itamar14/netrollout`, `-postgres`, `-nginx`). The zip is a compose project: `compose.yaml`, service configs, installer, management + update scripts.
- **Stack:** app, Postgres (pg_cron), Redis, nginx; optional monitoring profile (Grafana, Prometheus, Loki, promtail). **Only nginx publishes ports** (443, and 80→443 if free). Grafana through nginx at `/grafana`. `restart: unless-stopped` everywhere.

## Decisions (planning session 2026-09-30)
1. Windows (main) and Linux supported; the installer detects the OS. Windows = **Docker Desktop on Windows 10/11** (Windows 11 recommended; Win10 is past end of support). Windows Server is detected and refused (unsupported by Docker Desktop). Linux = Docker Engine + compose plugin.
2. VM prerequisites documented + checked: **nested virtualization**, vTPM + Secure Boot for Win11, ~4 vCPU / 8 GB RAM (16 GB with monitoring). **Auto-logon for a service account** so NetRollout comes back after reboots (Docker Desktop starts at sign-in).
3. **Licensing notice** before install — Docker Desktop terms (free only for small orgs; compliance is the org's), NetRollout AGPL v3, Windows client-VM licensing — the user must type **yes**; acceptance recorded in the install folder. Docker Desktop is **never bundled** — the installer links to Docker's official download.
4. **Installer questions** (`[default]`, Enter accepts): hostname [computer name], HTTPS port [443], monitoring [Y], organisation certificate path [none → self-signed], concurrent rollout jobs [4], timezone [UTC]. Generated silently: Postgres/Redis/Grafana passwords, `SECRET_KEY`, the Fernet encryption key. *(Revised from the session: the "internal app port" question is dropped — the app port is internal to the compose network and never published, so it can't clash; timezone added — containers run in UTC and the app stores naive local times.)*
5. **Data:** Postgres/Redis/Grafana/Loki in named volumes; `logs/`, `config/`, `certs/`, `backups/` as visible folders in the install folder.
6. **Management script** `netrollout` (.bat/.ps1/.sh): start, stop, status, open, logs, backup, restore, apply. Separate **update** script (auto-backup → new version → pull → up; migrations at app start). In-app "check for updates" is post-v1.0.
7. **Admin Restart** in a container: the app exits cleanly and the restart policy brings it back; refused while rollouts run (unless forced).
8. **Factory admin** stays `admin`/`admin` with a forced **change-password at first login** (blocking page).
9. **Certificates:** self-signed by default, organisation cert via the installer, and **upload in Server Management** (validated, applied live by nginx's watcher).
10. **Part C:** System Settings hostname applies live (nginx config rendered by the app, validated + reloaded by a watcher; other names redirect to the canonical hostname; a self-signed cert is regenerated for the new name). HTTPS port changes need `netrollout apply` (no host networking on Windows).
11. **CLI** as a PyInstaller `.exe`, built in CI.
12. **Release pipeline:** GitHub Actions on a `vX.Y.Z` tag.
13. **CDN assets stay** for v1.0 (bundling + offline image transfer post-v1.0).
14. **Squash the migration history** into one v1.0.0 baseline before release; dev DB `alembic stamp`ed.
15. **Platform profiles before v1.0** (found 2026-09-30): the push never commits on Junos / PAN-OS / IOS-XR and reports five platforms as failed (`save_config()` not implemented there), and verify is broken on 7 of 12 platforms — IOS-XE mapped to a non-existent NAPALM driver (`iosxe`), Juniper returned in curly-brace format so typed `set` commands never match, FortiOS/PAN-OS/Aruba CX/ProCurve NAPALM drivers not installed, and the verify connection ignores the device port. Fix: fetch the config via **Netmiko** (already the push library; all 12 platforms; honours the port) **in each vendor's typed syntax**; NAPALM dropped as a dependency. Deep Diff + `hier_config` + `netutils` stay in Phase 5b; an optional local-AI "explain this failure" is a post-v1.0 idea.

## Implementation — stages (each on its own branch, testable and committable)

**1. Hygiene.** `requirements.txt` fixed (add Flask-WTF; drop mypy, pytest, pip, utils, ipaddress, numpy, dotenv) + `requirements-dev.txt` + a pinned lock file; Python 3.12. `.gitattributes` (LF for .sh/nginx files, CRLF for .bat/.ps1). `.dockerignore` as a whitelist (`src/`, `templates/`, lock file only — keeps `docs/credentials`, `config.env`, `logs/` out). `LICENSE` (AGPL-3.0). **Migration squash** (decision 14): baseline from models, `alembic check` on a fresh scratch DB, stamp the dev DB.

**2. Paths + config precedence.** New `src/paths.py` decides folders: `NETROLLOUT_HOME` (image: `/data`), else the exe folder when frozen, else the repo root (dev unchanged); `logs_dir()`, `config_dir()`, `certs_dir()`. Callers: `logging_utils.LOGS_DIR`, `jobs.py` log lookups, `startup.DEFAULT_NGINX_CONF`, `backend._CONFIG_ENV`. Two config files: compose `.env` (installer-owned → container env) and `config/runtime.env` (app-owned, written only by Server Management, loaded with override) — precedence runtime.env > container env > defaults. Remove the unused `pending_db_init.flag` and `*_EXTERNAL` writes; fix `connection_modes()` to treat the compose hosts as bundled.

**3. Container runtime.** _(Revised 2026-10-01 with the developer: the startup proxy probe is dev-only; stop/Restart drain running rollouts.)_ Explicit `NETROLLOUT_DEPLOYMENT=docker`. Fail fast in a container on a missing `SECRET_KEY` or encryption key (never generate a key inside a container); in dev a missing `SECRET_KEY` gets a random per-run key + a warning (no `"dev"` fallback). **Drain** (one routine for SIGTERM and Restart): new rollouts are refused with a clear message and a banner; running rollouts finish; queued ones are marked cancelled ("server restarted before it started") instead of silently vanishing (job definitions live only in memory); bounded by a deadline (default 10 min, below compose's `stop_grace_period`) after which running jobs are cancelled with a record. Restart route (`admin_servers.py`): with rollouts running it answers 409 and the page offers "restart when rollouts finish" (drain) or "restart now" (cancel), in dev and container alike; container → drain + `os._exit(0)`, the restart policy (`unless-stopped`) brings it back. Startup message: in a container no proxy probing and no browser — one log line with the expected URL (System Settings hostname + HTTPS port); the host-side check is the installer and `netrollout status` calling `/_netrollout/health` (stage 9); the token probe stays for dev. `/metrics` → 404 in nginx, scraped by Prometheus at `app:8080`. Flask-Session reads the live Redis client (a Server Management Redis switch keeps logins working). New `/_netrollout/health`: Postgres/Redis status, running/queued rollouts, version; 200 when both services are up, else 503.

**4. Passwords: forced change, self-service change, admin reset.** _(Extended 2026-10-01 with the developer: until now no user could change a password.)_ Migration (the first on top of the baseline): `users.must_change_password` (true for `admin` while its hash is still "admin"); seeding sets it. One password rule everywhere (registration, change, generated): at least 8 characters with at least 2 of letters / digits / special characters, ASCII, not containing the username (so never "admin"); a change must differ from the current one. One `before_request` gate while the flag is set (allowlist: the change-password route, logout, static, instance/health): pages redirect to the change page, JSON/XHR gets 403. `/account/password` + `templates/change_password.html` (current + new + confirm) serves both the forced change and a voluntary one (a link on the Account page); rate-limited like login; audit `auth.password_change`; flag cleared; session rotated; the user's other sessions signed out. Admin "Reset password" for another local user: a random temporary password shown once to the admin, the stored password replaced, the flag set, the user signed out everywhere (every session, not only the latest), audit `user.reset_password` (never the password); not for LDAP users, the admin's own account or the factory `admin`. Local accounts only.

**4b. Platform profiles: push finalisation + verify (decision 15).** Found 2026-09-30 (netmiko 4.6.0): the push (`RolloutEngine._push_config`, `src/core.py:~229`) always calls `save_config()`, which is **not implemented** for Junos, PAN-OS, IOS-XR, FortiOS and Check Point → the device is reported failed, and **Junos / PAN-OS / IOS-XR changes are never committed** (not applied). One per-platform **profile table** replaces the `netmiko_to_napalm` map and the generic finish, defining for each platform:
- **finish the push:** `save_config()` for Cisco IOS/IOS-XE/NX-OS, Arista, Aruba CX, HP ProCurve/Comware; **`commit()`** before leaving config mode for Junos, PAN-OS, IOS-XR (commit errors reported as failure with the device's message); `save config` for Check Point Gaia; nothing extra for FortiOS (applies on `end`);
- **fetch the config** (below) and **the matcher**.
Adding a vendor = one profile row + a fixture test (if Netmiko supports it).

Verify: replace `Device.fetch_config` (`src/core.py`, NAPALM `get_config`) with a per-platform fetch over Netmiko, using the device's port and credentials, asking for the config in the syntax engineers type:
- Juniper: `show configuration | display set` (`delete …` commands → the line must be absent);
- PAN-OS: `set cli config-output-format set` + `show config running`;
- Check Point Gaia: clish `show configuration` (`set …` lines — Check Point gains verify);
- FortiOS: `show` (block syntax `config/edit/set/next/end`, matched by a small block-aware parser);
- Cisco IOS/IOS-XE/NX-OS/IOS-XR, Arista, Aruba CX, HP ProCurve/Comware: `show running-config` (line matching as today, section-aware).
Verify reports per command; platforms without a matcher say so explicitly. Removals (`delete …`, `no …`) are checked as "must be absent" within their section (so `no shutdown` passes when `shutdown` is gone from that interface). Operational commands that leave no trace in the config (`clear …`, `write memory`, `copy …`, per-platform list) are reported as **"not verifiable"** instead of failing. Known remaining limits (documented, solved in 5b): typed abbreviations, values the device rewrites (hashed secrets, reformatting, hidden defaults), and "already present before the rollout" false positives. Remove `napalm` from requirements. Update the Verify tooltip on New Rollout to describe the new behaviour. Tests: per-platform fixtures (recorded config output + commands → expected verified/failed lines), including `delete`, `no …` and FortiOS nested blocks; a port-forwarded device fetch uses its port. Real-device check: the EVE-NG round (release gate).

**5. CLI `.exe`.** Decouple `src/cli.py` from the DB/web stack (`core.py` imports `Inventory` only for typing → `TYPE_CHECKING`; lazy `redis` import in `logging_utils`), guarded by an import-isolation test. Logs next to the exe (`paths`). `netrollout-cli.spec` with netmiko/ntc-templates data (no NAPALM after 4b); `--version`.

**6. Images.**
- App: multi-stage `python:3.12-slim`, non-root user, `NETROLLOUT_DEPLOYMENT=docker` + `NETROLLOUT_HOME=/data`, the version into `src/version.py` from the tag, `/data/{logs,config,certs}`, health check, version label + footer version/source link (AGPL §13).
- `src/tools/certs.py` (runs inside the app image — no OpenSSL on the host): `selfsigned` (ECDSA, SANs, atomic write, `.selfsigned` marker) and `validate` (key↔cert, hostname/SAN incl. wildcards, expiry, rejects encrypted keys) — shared by the installer and the upload route.
- Postgres: `postgres:17` + pg_cron, `shared_preload_libraries` + `cron.database_name` set; init script creates the app role, `grafana_reader` and the cron grants; `install()` applies idempotent Grafana read grants after migrations (sensitive tables excluded).
- nginx: `nginx:alpine` + bootstrap template + a **polling watcher** (hash rendered config + certs every few seconds → `nginx -t` on staging → reload if valid, else keep last-good; writes `status.json`). Config: Docker DNS resolver + variable upstream (no stale-IP 502 after Restart), SSE location for `/rollout/stream/`, `/metrics` → 404, `/grafana/` with WebSocket headers when monitoring is on, default server redirecting to the canonical hostname; the port-80 server (when 80 is free) redirects to `https://<canonical host>:<HTTPS port>` — the configured port, so users who type just the name land on a non-default port too.

**7. `deploy/` compose + monitoring configs.** Move `docs/{nginx,prometheus,loki,promtail,grafana}` to `deploy/` (rename `dashbaord_config` → `dashboards`). `compose.yaml` (`name: netrollout`; service names `postgres` / `redis` (stage 2's bundled check); app: `init: true` (as PID 1 Python ignores a SIGTERM that arrives before its handler is installed) and `stop_grace_period` above `NETROLLOUT_DRAIN_SECONDS` + 60 s (stage 3 container test: `StopTimeout=1` was observed without any setting, so `docker stop` killed the app after 1 s); health check on `/_netrollout/health`; profiles; health checks; `depends_on: service_healthy`; pinned versions; named volumes + bind folders; Redis password + AOF). Fix: Prometheus target `app:8080`; promtail timestamp regex + `TZ`; Grafana datasource host + sub-path settings + generated admin password; Loki retention. Admin sidebar "Monitoring" link when enabled.

**8. Part C + certificate upload.** `src/webapp/proxy_config.py` renders the nginx config from System Settings (atomic write + generation marker), reads the watcher's `status.json`. Saving the hostname → render, regenerate a self-signed cert if in use, show "Applied / Rejected: <nginx error>". Saving the HTTPS port → `config/desired.env` + "run `netrollout apply`" ("apply pending", like restart pending); redirects keep using the published port until applied. In a container the System Settings *Test* button shows the watcher's status (Applied / Rejected + the nginx error) instead of stage 3's "run `netrollout status`". Server Management certificate upload (validate, write, bump generation, show subject/SAN/expiry, audit).

**9. Installer + scripts** (release zip layout: `install/netrollout/update` in .bat+.ps1+.sh, `compose.yaml`, `.env.example`, service configs, `LICENSE`, `README.md`, `VERSION`). `install.ps1` (PowerShell 5.1-compatible, launched by `install.bat` with ExecutionPolicy Bypass): an existing install in the folder is detected (point to `netrollout status` / `update`, never re-initialise) → licence "yes" → refuse Windows Server → virtualization check with Hyper-V/VMware guidance → Docker check + wait loop → questions (port-free checks for 443/80) → secrets → `.env` written UTF-8 **without BOM**, ACL-restricted → folders → certificate via the helper container → `compose pull` + `up -d --wait` (on failure show `ps` + app logs) → URL (hostname **and** IP; the self-signed certificate carries the IP as a SAN) verified from the host via `/_netrollout/health` + "sign in as admin/admin and change the password now" + a desktop shortcut on the server → auto-start/auto-logon guidance. `install.sh` mirrors it (Docker Engine, `chown` of bind folders). Non-interactive flags (`--yes --defaults`) for CI. `backup` uses `pg_dump -Fc` written inside the container to `./backups` (never piped through PowerShell) + config/certs/.env zipped with a secrets warning; `restore`; `apply`; `status` (URL, health from the host, containers, running rollouts); `stop`/`update` warn when rollouts are running and wait for the drain; `update` (auto-backup → release zip via GitHub API → pull → up).

**10. CI.** `ci.yml` on push/PR: unit + integration tests (pg_cron Postgres + Redis service containers), ShellCheck, PSScriptAnalyzer. `release.yml` on `v*.*.*`: tests → build + push the three images (`vX.Y.Z` + `latest`, linux/amd64) → compose smoke test on Ubuntu with the non-interactive installer (instance, `/metrics` 404, Grafana health, admin forced to change-password) → Windows runner builds the `.exe` + `--help` smoke → zip + SHA256SUMS → `gh release create`. Secrets: `DOCKERHUB_USERNAME`, `DOCKERHUB_TOKEN`.

**11. Docs + release.** README (quick start, requirements, CLI, CSV format, backup/restore, update, certificates, `apply`, monitoring URL, security posture, "Can't find NetRollout?" — `netrollout status`/`open`, the 80→443 redirect, `.env`), `docs/deployment.md` (VM prerequisites, auto-logon, firewall), CLAUDE.md + workplan updates. Tag **v1.0.0** after the gates below.

**Dependencies:** 1 → 2 → {3, 4, 4b, 5} → 6 → 7 → 8 → 9 → 10 → 11 (4b before 5 so the exe is built without NAPALM).

**Phase 5b (post-v1.0, recorded):** Deep Diff (config before + after, `config_before`/`config_after` columns) with **`hier_config`** as the comparison engine and **`netutils`** for normalization (e.g. interface abbreviations); Junos can use its own commit diff (`show | compare rollback 1`). Post-v1.0 idea: optional **local-AI "Explain this failure"** — small quantized model on the server, on demand per failed device, only the relevant diff/section sent, advisory only (never the pass/fail verdict), no cloud.

## Verification
- Every stage: the full pytest suite + new unit/integration tests; nothing starts against the live dev DB (scratch DB + Redis db 15 + spare port harnesses only).
- Images/compose: `docker compose --profile monitoring up -d --wait` on the developer's Windows PC — instance endpoint through nginx, `/metrics` 404, Grafana `/grafana/api/health`, dashboards reading Postgres/Prometheus/Loki, Loki timestamps correct, pg_cron jobs in `cron.job`, Restart button returns without a lasting 502.
- Stop / Restart with a real rollout (stage 3 proved SIGTERM → drain → exit 0 only with the app idle, and the drain with fakes): `netrollout stop` and the Restart button during a running lab rollout — banner shown, the rollout completes and is recorded, a queued one shows as cancelled in Results, exit 0; Restart brings the container back (`unless-stopped`).
- Part C: hostname change applies live and old names redirect; organisation cert upload applies without restart; a bad cert is rejected while service continues; HTTPS port + `apply`.
- Installer: full run on the developer's PC (engineer's-PC scenario); CI runs the non-interactive Linux install.
- **Release gates for v1.0.0:** first login forces the password change; backup → restore onto a fresh install keeps data and encrypted credentials; upgrade rc1 → rc2 keeps data; the EVE-NG round against the built image — push + verify on Cisco IOS/IOS-XE plus, where available, **Juniper, PAN-OS and IOS-XR (the new commit path)** and FortiOS — through both the web app and the CLI `.exe`; image inspection shows no `docs/credentials`/`config.env`. LDAP is documented as tested against OpenLDAP; Active Directory testing (ephemeral Samba DC) is a gate only if v1.0 claims AD support. Win11 VM (nested virtualization + auto-logon reboot) and Ubuntu installs are verified when a VM is available.
