Push one change to every device, and prove it landed.

NetRollout sends configuration over SSH to many network devices at once and proves every command by the device's own configuration, before and after. What it can't prove, it doesn't guess: it hands it to you with the evidence. Easy to run, and correct because it never claims more than it proved. Self-hosted and open source, for network engineers and their teams.

One rollout, start to finish

The same four steps whether it's three switches or three hundred, in the web app or from the command line.

  1. Pick the devices

    From your inventory, by label or one by one. Credentials live in encrypted security profiles, never in the rollout.

  2. Write the change once

    Tokens fill in each device's own values, so one snippet fits the whole fleet.

    interface Loopback0 ip address $$LO_IP$$ 255.255.255.255

  3. Push in parallel

    Devices run side by side within your limits, and each platform saves or commits in its own way. Watch it live, device by device.

  4. Prove it and keep the record

    Each device's configuration, before and after, proves every command, removals included. Whatever it can't prove waits for your decision. Results, logs and snapshots are stored; roll back from there.

Not just sent. Proven.

NetRollout reads each device's configuration before the push and again after it, and compares the device with itself. A command is proven when its line appears, is already there, or is gone as asked, however the device abbreviates or numbers it. No list of error messages decides anything, and a quiet device proves nothing: what the configuration doesn't prove goes to you, with the device's line and its reply.

NetRollout> verify 10.20.1.14:22 (cisco_ios, before → after)
int lo0 + interface Loopback0 took effect
ip address 192.0.2.11 255.255.255.255 + ip address 192.0.2.11 255.255.255.255 took effect
no ntp server 192.0.2.9 - ntp server 192.0.2.9 removed
logging host 192.0.2.50 logging host 192.0.2.50 already in place
ntp server 192.0.2.123 no change in its section review
the device replied: % Initialization of NTP failed with status 4.
4 of 5 proven: review confirm or reject it in Results → Verification

Made for a team, not a laptop

Everything around the push that a shared tool needs.

Accounts and sign-in

Operator and admin roles, local accounts with approval, LDAP with group rules, two-factor sign-in, and lockout after repeated wrong passwords.

Live logs, safe to share

Follow every rollout as it runs. Passwords, secrets and SNMP communities are replaced with <redacted> in every log.

Results, review and rollback

Every device's status and log, and its Verification: each command's verdict with the device's line and reply, and the diff with each line's command. Confirm or reject what NetRollout couldn't prove, on record. Cases only a person can fix are flagged ACTION NEEDED.

Audit log

Sign-ins, rollouts, setting changes and admin actions, recorded with who and when.

Monitoring

Optional Prometheus, Loki and Grafana, with ready-made dashboards for operations, jobs and security.

Backups and upgrades

Scheduled backups, one-step restore, and upgrades that back up first and can be finished if interrupted.

Yours, on your network

NetRollout runs on a server you control, next to the devices it manages.

  • Runs in Docker on Windows or Linux. The installer sets it up: passwords, keys, a certificate, and a service that starts with the machine.
  • No internet needed once it's installed, except to download upgrades. Nothing phones home.
  • Credentials are encrypted at rest, and the app's logs are safe to share.
  • Free software under the GNU AGPL v3. Read the code, change it, run it.
  • A CLI too: one .exe for a one-off rollout from a CSV and a commands file, with no install at all.
